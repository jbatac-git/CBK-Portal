# CBK Portal: Key decisions

- Project: internal employee portal (NOT an LMS)
- Stack: Laravel 12, PostgreSQL, React + TypeScript, Inertia, Tailwind
- Roles: Super Admin, Admin, HR, Diser
- Login: username (not email)
- Palette: maroon #7A1421, dark maroon #5C0F19, gold #C9973F, cream #FBF6F0
- Learning materials: private storage, view-only, watermark
- Careers: disabled in Phase 1
- Temporary access: 7 days, then Approve / Not approve
- Diser module access = DIRECT per-user permissions (portal.learning, portal.price-lists, portal.contact-us). Spatie cannot subtract role permissions, so the Diser role only has portal.access.
- Access checks use permissions, never role names.
- Role hierarchy: Super Admin > Admin > HR > Diser (RoleName::rank()). A user may create/edit only accounts ranked below their own; Super Admin may manage anyone.
- Username = first initial + last name + last 2 digits of Employee ID (lowercase, a-z0-9). On collision, widen to 3, 4... digits. Never regenerated.
- Temporary access = 7 days (config/portal.php). Password = 12 random chars, stored hashed, emailed via encrypted queued mail.
- Only users with users.manage-access (Admin, Super Admin) choose Diser modules. HR gets defaults on create and cannot change them.
- Role changes after creation are NOT part of Phase 2.
- Known gap (closed in Phase 3): a temporary Diser still sees all assigned modules; the "learning only" restriction is enforced in Phase 3.
- Account state machine lives in AccountStatus::canTransitionTo(). Temporary -> Active|Restricted|Deactivated; Restricted -> Active|Deactivated; Active -> Deactivated; Deactivated is final (rehire = future phase).
- Every status change goes through AccountLifecycleService::transition() and records status_changed_at / status_changed_by (NULL = system).
- Immediate access removal = per-request middleware + delete DB sessions + rotate remember_token (SessionRevoker). Requires SESSION_DRIVER=database.
- accounts:expire-temporary runs hourly; it only cleans up state. The middleware already blocks expired accounts at once. Production needs a cron for schedule:run.
- Temporary Diser (no admin.access) may only open routes in config('portal.temporary_allowed_routes'); other temporary roles keep their admin tools.
- Nobody may approve/restrict/deactivate their own account. Deactivate = Admin, Super Admin. HR sends removal requests; Admin/Super Admin process them. One pending request per employee (partial unique index).
- Resend credentials: only while temporary, before the first password change, before expiry; never extends the 7 days.
- Force password change on first login (must_change_password). Completing a Breeze password reset also clears the flag.
- Price lists are NOT protected like learning materials (direct download via public disk) — business decision, confirm with CBK.
- Profile photos and the portal logo use the `public` disk (not sensitive); learning materials stay on `local`.
- Image uploads are cropped client-side (react-easy-crop) AND resized server-side (Intervention Image) to a fixed size, so the final size is never trusted from the client alone.
- Roles & Permissions UI only edits Admin and HR. Super Admin always keeps every permission (re-synced on every save as a safety net). Diser has no toggleable role permissions here — Diser module access is per-employee, managed in User Management.
- Editable permission set for the matrix excludes admin.access/portal.access (base entry) and settings.manage/roles.manage (Super-Admin-only by design).
- Profile lets a user change: contact number, photo, password. Name, email, username, and employee ID remain HR/Admin-managed.
- Profile is locked during the 7-day temporary access period (matches the spec's "Approved" employees only).
- Gotcha: a dot in a Form Request rule key ALWAYS means "nested array path" in Laravel, never a literal flat key. Settings forms (Contact Us, Footer) must send true nested arrays (`contact: {...}`, `footer: {...}`), not flat keys like `contact.headline`. PortalSettingService::stripPrefix()/addPrefix() convert between that nested HTTP shape and our flat dot-keyed DB storage shape.
- Gotcha: UploadedFile::fake()->create() does NOT write real file bytes — only a faked reported size. Any test that relies on real content-sniffing (our finfo-based MIME check) must use UploadedFile::fake()->createWithContent() with genuine signature bytes (e.g. "%PDF-1.4...") instead.
- `RedirectsWithDomainErrors` must be used via `use RedirectsWithDomainErrors;` directly in the controller class — never through an anonymous class, since its `attempt()` method is `protected` and not accessible from outside that scope.
- Company, Department, and RemovalReason are now admin-manageable (settings.manage, Super Admin only) via a shared LookupService + ManagesLookupResource trait — same CRUD shape (name + is_active, protected from deletion while in use), avoiding 3x duplicated code.
- RemovalReason moved from a hardcoded PHP enum to a `removal_reasons` table so new reasons can be added without a code deploy. The 3 defaults (Resigned, AWOL, Separated) were seeded directly inside the migration that converted removal_requests.reason into removal_reason_id, so existing data backfilled correctly.
- Assumption: only Super Admin manages Company/Department/RemovalReason (bundled under settings.manage like Logo/Footer). Confirm with CBK if Admin should also have this.
- Error pages: Inertia's documented `$exceptions->respond()` pattern renders resources/js/Pages/Error.tsx for 403/404 always, and for 500/503 only when APP_DEBUG=false (so local development still shows real stack traces).
- Dashboard stats are permission-gated per card in DashboardService::statsFor(); the frontend only owns label/icon presentation.
- Careers is a feature flag only (`features.careers_enabled` in portal_settings), toggled via its own dedicated route (admin.settings.careers.update) — deliberately NOT bundled into the Logo/Footer save, to avoid accidentally resetting it when only the logo changes. The Diser nav item stays `ready: false` regardless of the flag, since no actual Careers page exists yet.
- SecurityBoundaryTest reads the live route registry (not a hardcoded list) to test every parameterless admin/portal route against the wrong role. Any future module whose routes are accidentally left outside the correct middleware group will fail this test automatically.
- Bug fix: Dashboard stat counts now use User::scopeVisibleTo(), the same hierarchy scope UserAccountService::list() already used — previously they counted globally, mismatching the table. Side effect (by existing design, not new): Admin does not see other Admins or their own account in either the table or the Dashboard count — only Super Admin sees everyone.
- Careers nav item is now hidden entirely (not shown as disabled "Soon") when features.careers_enabled is false, and links to a real (minimal) Portal/Careers/Index page when true. The page itself still 404s server-side if accessed directly while the flag is off — backend is the real boundary.
- Avatar initials now derive from first_name[0]+last_name[0] directly (passed through from AuthUser/Employee), not a split of the full display name (which could include a middle name and produce wrong initials).
- User Management table: avatar + name/email merged into a single clickable cell that opens the View modal, replacing the separate Photo column and "View" text link.
- Companies, Departments, and Removal Reasons now share one "Maintenance" sidebar item and one Index page with a tab switcher (MaintenanceController + LookupService), reusing the existing per-entity Create/Edit/Store/Update/Destroy routes unchanged.
- Security fix: Diser module permissions (portal.learning / portal.price-lists / portal.contact-us) are now enforced by route middleware on each portal module, not only by hiding nav items. Home only includes the materials preview when the user has portal.learning.
- Concurrency fix: AccountLifecycleService::transition() re-reads the user under lockForUpdate() inside a transaction, and RemovalRequestService locks the request row before approve/decline, so two simultaneous actions cannot both pass a stale status check (e.g. Approve resurrecting a just-Deactivated account). expireOverdue() skips accounts whose status changed after the chunk was loaded.
- Learning material category slugs are generated once on create (numbered if the slug already exists, including soft-deleted rows) and are never edited; names must be unique among non-deleted categories.
- Video materials may play from an external link (`external_url`) instead of an upload: YouTube, Vimeo, Google Drive, or any https .mp4/.webm. PDFs are always uploads. VideoEmbed rebuilds the embed URL from the parsed ID (never echoes the raw link into an iframe); link videos have no stream URL and the stream route 404s for them. Switching a video upload -> link deletes the stored file after the DB update.
- Learning pages use deterrents only (browsers cannot block OS screenshots or cameras): content is shielded on window blur / hidden tab / PrintScreen, save/print/devtools shortcuts, context menu, copy and drag are blocked, the viewer is hidden in print, and a tiled watermark (full name, username, date) makes captures traceable. Fullscreen is applied to the viewer wrapper so the watermark stays visible.

## UI conventions (buttons and layouts)

- Button hierarchy: one **primary** (maroon) action per view; **secondary** (white, bordered) for alternatives such as Cancel, Filter, Categories; **ghost** for low-emphasis actions; **danger** (red) only to confirm a destructive action inside a ConfirmDialog.
- Labels are verb + noun in sentence case. Create = "Add {item}" (page title, header button and submit button all match). Edit and settings = "Save changes". Icons on buttons only for create (Plus) and upload/change-file actions.
- Index pages: PageHeader (title, one-line description, primary "Add {item}" on the right) → Toolbar (search, filters, "Filter") → Table with pagination in its footer.
- Table rows: Edit = pencil IconButton with tooltip; decisions (Approve/Decline) = small buttons; everything else (Archive, Delete, Activate/Deactivate, Re-send) in the "⋯" Menu with a ConfirmDialog for destructive items; status is always a Badge, never an inline switch.
- Create/edit pages: max-w-3xl, PageHeader with a back link (edit pages add an "Edit {item}" eyebrow), form sections as Cards, and the shared sticky FormActions bar (Cancel, then primary submit).
- Settings-style pages: left description column + right Card per section, each section saving on its own with "Save changes" in its CardFooter. Switches are only used inside forms.
